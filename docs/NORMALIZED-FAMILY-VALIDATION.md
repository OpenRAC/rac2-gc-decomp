# Normalized family validation pilot

The GS buffer setup pilot confirms that normalized discovery can identify a
reusable C body while acceptance still requires every unmasked reference byte.
This is one already integrated family, not a certified unique-code denominator
or new C progress.

The maintained [normalized family workflow](NORMALIZED-FAMILY-WORKFLOW.md)
provides public discovery and reviewed binding-preparation tools. The checked GS
spec reproduces this method through the existing campaign trial route, with
private immutable evidence and unchanged exact acceptance.

## Interpretation and limits

This proves complete-symbol reuse for this known family with the correct
placement bindings, and demonstrates why a masked signature cannot accept a
match. The 136-byte body represents 3,672 existing placement bytes; **new
integration credit is zero**. This pilot does not recompile complete overlay
images or establish gameplay behavior. Existing complete-unit/full-image
integration proofs remain unchanged.

A separate bounded retail review also retains a pair of 92-byte inferred
Aranos bodies at `0x002F08D0` and `0x002F0930`: the RAC1 heuristic groups them
despite different packet-producing constants. They must remain explicit
variants. Normalization can therefore both reveal valid reuse and conceal
meaningful differences; the approximate 5.14 MB grouping remains provisional.

Use normalized signatures for discovery, inspect all altered fields and their
bindings, retain constant/layout variants, and qualify each complete placement
without masking. Authored-source reuse and exact loaded-byte coverage are
separate measurements. See [the campaign workflow](CAMPAIGN-WORKFLOW.md).
Private sources, objects, references, logs and independent receipts remain in
the runtime bank referenced by the register; only this method and proof metadata
are versioned.
